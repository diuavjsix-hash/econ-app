# UI 공통 규칙

이 문서는 현재 앱의 기능을 추가·수정할 때 따르는 기준입니다. 필요한 도구와 조작을 바로 찾고, 한 도구에서 익힌 표시를 다른 도구에서도 이해할 수 있게 합니다. 전체 앱을 새 컴포넌트 체계로 바꿨다는 의미는 아닙니다. 아래 **맞춤 UI**는 공통 코드로 구현되어 있습니다.

## 화면 구성

- 도구막대는 짧은 기능 이름과 아이콘을 함께 사용하고 활성 도구만 강조합니다. 생성·선택·복제·합산 등 현재 작업은 하나만 활성화합니다.
- 오른쪽 편집 패널은 `editorContext`가 정하는 현재 작업 하나를 보여 줍니다. 도구마다 별도 패널 전환 규칙을 추가하지 않습니다.
- 설명은 필요한 조작 중심으로 짧게 씁니다. 같은 안내를 도구막대 아래와 패널 안에 반복하지 않습니다. 실패는 작업 가까이에 짧게 알리고 불필요한 확인 창을 추가하지 않습니다.
- 삭제·복제 같은 공통 명령, 이름·진하기 같은 입력은 기존 클래스와 기록 묶음을 재사용합니다. 입력란의 기본 편집·모바일 줄바꿈·키보드 포커스를 유지합니다.

## 맞춤 UI의 단일 구현

| 코드 | 책임 |
| --- | --- |
| `src/graph/snap-policy.js` | 화면 거리 16px 포착·24px 유지/해제와 일반 후보 유지/우선순위 |
| `src/graph/snap-feedback.js` | 후보 정규화·공통 문구·대상 강조·원·문구 배치 |
| `src/graph/snap-feedback.css` | 공통 색·선 굵기·투명도·글꼴·맞춤된 미리보기 강조 |
| `src/graph/sketch-magnets.js` | 곡선 생성의 실제 직선 접점 후보와 포착 유지 |
| `src/graph/snap.js`, `dashed-magnets.js`, `tangency.js`, `intercepts.js`, `point-magnets.js` | 도형별 기하·제약·유효 후보 계산 |
| `src/graph/canvas.js`의 `updateSnapFeedback` | 현재 조작 후보 하나를 선택해 공통 렌더러에 전달 |

점 생성/이동, 점선 생성/끝점/전체 이동, 자유 곡선 생성/세 점 편집, 직선·기본/자유/무차별곡선 전체 이동의 맞춤은 모두 하나의 `.snap-feedback-layer`를 사용합니다. 새 도구가 원·문구·대상 강조용 SVG/CSS를 별도로 만들면 안 됩니다.

## 표시 규칙

| 상태 | 표시 |
| --- | --- |
| 자유 포인터 | 반지름 9px의 점선 원 하나와 좌표; 터치에는 자유 마우스 포인터를 그리지 않음 |
| 맞춤됨 | 반지름 11px 외곽 원 + 5px 중심 원, 공통 보라색, 실제 대상 획의 옅은 강조 |
| 점에 맞춤 | 같은 이중 원을 쓰되 중심 점의 기존 회색을 유지 |
| 점선/생성 곡선 맞춤 | 위 표시와 함께 현재 미리보기의 획도 같은 색으로 강조 |
| 맞춤 해제·Alt | 맞춤 강조를 지우고 자유 상태로 복귀 |

색은 CSS의 `--snap-color`, 원 크기·문구 간격은 JS의 `SNAP_MARKER`를 수정합니다. 도구별 숫자/색 복사본을 추가하지 않습니다. 목표 획은 현재 보이는 기하를 강조합니다. 축 간격으로 숨긴 획을 새로 그리지 않되, 절편/원점 후보와 축 강조는 기존 기하 규칙을 유지합니다.

공통 문구는 **선 맞춤 · 축 맞춤 · 점 맞춤 · 교점 맞춤 · 접점 맞춤 · 꺾임 맞춤 · x절편 · y절편 · 원점**입니다. 모서리 등 기하 의미가 다른후보는 기존 명시적 `label`을 유지합니다. 생성·좌표 편집에는 좌표를 덧붙이고 전체 도형 이동에는 짧은 문구만 표시합니다. 글씨는 마커 아래쪽에 두며 캔버스 가장자리에서는 위치를 보정합니다. 극단적으로 좁은 화면에서는 글씨 폭을 줄여 내부에 유지합니다.

대상·마커·문구는 전부 `pointer-events:none`이며 한 시점에 맞춤 마커는 하나입니다. 실제 점·손잡이·세 점 생성의 시작/끝 표시 같은 편집 요소는 별도 역할을 유지합니다.

## 후보 전달 형식

```js
{
  point: { x, y },              // 보정된 수학 좌표
  kind: 'shape',               // free / shape / point / intersection / tangent / kink / intercept
  ids: ['line-1'],             // 강조할 도형/axis-x/axis-y; sourceId 한 개로도 전달 가능
  sourceId: 'line-1',           // 선택 사항
  label: '꺾임 맞춤',          // 선택 사항; 기본 문구는 공통 렌더러가 결정
  axis: 'x'                    // 절편 후보에서 x / y / origin
}
```

`snapFeedbackModel`이 도형별 `ids`/`sourceId`를 정규화합니다. 계산용 `anchor`, `geometry`, `key`, `line` 등은 렌더러가 수정하지 않습니다. 대상 경로는 공통 `snapFeedbackTargets`가 현재 상태와 viewport에서 가져옵니다. 화면 좌표·SVG·맞춤 후보는 문서/JSON에 저장하지 않습니다.

## 반응과 의미

- 모든 자석은 16px 안에서 새로 잡고 같은 유효 후보는 24px까지 유지합니다. 거리 판단은 포인터나 실제 보정량의 화면 거리이며 Shift 잠긴 좌표를 바꾸지 않습니다.
- Alt는 후보 계산과 표시를 모두 생략합니다. Alt/Shift 변경은 포인터가 멈춰 있어도 진행 중인 조작에 반영합니다. 입력란/열린 dialog의 기본 키 동작을 가로채지 않습니다.
- 점·교점 우선과 기존 유효 후보 유지 규칙을 지킵니다. 같은 축/획을 따라가는 중에도 더 구체적인 점·교점이 잡힐 수 있습니다.
- 꺾임 같은 유한 꼭짓점은 두 선분만 등록하지 않고 명시적 점 후보(`kink`)도 제공합니다. 점·점선은 꼭짓점을 정확히 잡고, 이미 붙은 팔에서 가까워지면 꼭짓점으로 전환해야 합니다. 화면 밖/축 간격에 가려진 꼭짓점은 제외하고 Shift 잠긴 좌표가 다르면 선분의 허용 교차점만 사용합니다.
- 곡선의 세 번째 점을 직선에 붙여 생성할 때는 기존 tangent binding을 만듭니다. 도형 전체 이동의 자석은 모양/기울기를 유지하는 일시적 위치 보정이며 새 binding을 만들지 않습니다. 공통 표시는 이 의미를 변경하지 않습니다.
- 연결된 손잡이의 제약이나 유효성 검사 때문에 이동이 반영되지 않았다면, 실제 도형이 채택하지 않은 위치에 맞춤 표시를 띄우지 않습니다.
- 포인터 놓기/취소·도구/그래프/기록 전환에서는 이전 조작의 맞춤 상태를 버립니다. 생성 도구가 계속 켜져 있으면 다음 생성용 hover는 새로 표시할 수 있습니다.

## 변경 절차와 검증

1. 새 도형의 계산 모듈이 유효 후보를 반환하도록 구현하고 공통 포착/해제 상수를 사용합니다.
2. `updateSnapFeedback`에서 현재 조작 후보로 연결합니다. 새 표시가 필요하면 공통 모델·대상 기하·렌더러를 확장합니다.
3. 공통 스타일 변경은 점선·점·곡선 생성·직선/곡선 이동에 함께 확인합니다.
4. 자유/맞춤/해제·Shift·Alt·표시 ON/OFF·축 반전·화면 밖/축 간격·모바일·취소/기록·중복 마커 없음·입력 통과를 검사합니다.
5. 수학 좌표·모양·관계·undo/redo·JSON이 유지되는지 확인하고 HANDOFF와 검증 문서에 실제 확인 범위를 기록합니다.

자동 검증은 `tests/snap-feedback.test.js`와 기존 기하 회귀를 사용합니다. 실제 캔버스 통합 재현은 `.local/snap-feedback-integration-check.html`에 보관하며 필요할 때 public에 임시 복사해 실행하고 빌드 전에 제거합니다. 물리 포인터 검증과 합성 이벤트 검증은 구분해 기록합니다.
